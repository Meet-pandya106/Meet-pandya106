## Noesis — An Experience-Driven Developing Artificial Mind

Noesis is an open-source AI research program investigating how an artificial cognitive entity (NOUS) can progressively develop its internal representations, episodic memory, decision-making, and neural structure purely through accumulated environmental experience.

**The core research question:** How does accumulated experience cause measurable, permanent development in an artificial mind's structure — moving beyond static weights and black-box models?

**Architecture — Noetic Dynamic Graph (NDG):**  
A 2-level inspectable cognitive architecture combining modular functional regions (Perception, Integration, Memory, Prediction, Evaluation, Action) with a dynamic neural graph. The graph grows new nodes under developmental pressure and prunes redundant pathways — mimicking structural plasticity in biological neural systems.

**Key technical details:**

- **Neuromodulated plasticity** — Global surprise, prediction error, and novelty signals modulate local Hebbian and error-driven learning rates in real time. The system doesn't just learn; it regulates *how aggressively* it learns based on environmental context.
- **Full observability** — Every computational node has a unique identity, lifecycle log, and causal trace. Signal propagation, candidate action evaluations, and memory retrieval can be visualized live. No black boxes.
- **Experimental environment** — Interfaces directly with Game Boy Advance emulation (Pokémon FireRed) via custom mGBA Lua/TCP IPC sockets for rich sequential decision-making and continuous state extraction.

**Stack:** Python, PyTorch, mGBA / Lua Scripting, Dynamic Graph Networks, Continual Learning

## How I Approach Building

I don't plan everything upfront and I don't follow tutorials step-by-step. My process looks more like this:

1. **Pick a problem slightly beyond my current ability.** If I already know how to build it, it's not worth building.
2. **Design the architecture with AI as a thought partner.** Explore tradeoffs, sketch out data flow, decide on the stack.
3. **Build the core loop first.** Get something working end-to-end before worrying about polish. Ship ugly, then iterate.
4. **Break it intentionally.** Push edge cases, stress-test assumptions, find where the design falls apart.
5. **Document what I learned.** The project is secondary to the understanding I gain from building it.

This is why my repos range from cognitive architecture research to 3D dashboards to incident management tools. I follow curiosity, not a prescribed learning path.
