## What I'm currently working on

**Noesis — An Experience-Driven Developing Artificial Mind**

My primary research focus. Noesis investigates a single question: *how does accumulated experience produce measurable, permanent development in an artificial mind's structure?*

The system is built around a cognitive architecture called the **Noetic Dynamic Graph (NDG)** — a two-level inspectable graph that combines modular functional regions (Perception, Integration, Memory, Prediction, Evaluation, Action) with a dynamic neural substrate. The graph grows new nodes under developmental pressure and prunes redundant pathways, loosely analogous to structural plasticity in biological systems.

What makes it different from a standard neural network:
- **Neuromodulated plasticity** — surprise, prediction error, and novelty signals modulate local learning rates in real time. The system regulates *how aggressively* it learns, not just *what* it learns.
- **Full observability** — every node has a unique identity, a lifecycle log, and a causal trace. Signal propagation and memory retrieval can be watched live. No black boxes by design.
- **Grounded in sequential decision-making** — the experimental environment interfaces with Game Boy Advance emulation (Pokémon FireRed) via custom mGBA Lua/TCP IPC sockets, providing rich, continuous state for the agent to develop within.

Stack: Python · PyTorch · Dynamic Graph Networks · Continual Learning · mGBA / Lua Scripting

## Other projects here

**[Chronos-OS](https://github.com/Meet-pandya106/Chronos-OS)**  
A 3D hardware telemetry dashboard built with Electron, Vite, Three.js, and raw GLSL shaders. Streams real-time OS metrics and renders a 100k GPGPU particle simulation. An evidence-driven incident management platform for engineering teams. Handles root-cause analysis, structured resolution workflows, and verification with a privacy-first architecture. Built because incident tooling is usually either too lightweight or too bureaucratic — I wanted something in between.

## How I approach building

1. **Start with a problem that exceeds my current ability.** If I already know how to solve it, it's not the right problem.
2. **Use AI as a thinking partner, not a code dispenser.** Architecture tradeoffs, data modeling, API surface design — I want to understand the reasoning, not just the output.
3. **Build the core loop before anything else.** Get something working end-to-end before worrying about robustness or polish.
4. **Break it deliberately.** Stress-test assumptions, push edge cases, find where the design falls apart. The failure modes are usually more informative than the happy path.
5. **Document the understanding, not just the code.** The project is the vehicle. The point is what I learn by building it.
